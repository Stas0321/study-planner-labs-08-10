# Відповіді на контрольні запитання

1. **Компонент** — функція, що повертає React-розмітку. Компоненти ділять інтерфейс на незалежні частини, які можна повторно використовувати.
2. **JSX** — синтаксис розмітки всередині JavaScript; TSX — у TypeScript. Він перетворюється на JavaScript, використовує className, camelCase для подій і вирази в дужках; це не HTML-рядок.
3. JSX-вираз має один корінь, щоб утворювати єдиний результат. Fragment групує елементи без додаткового DOM-вузла.
4. JavaScript-вираз записують у фігурних дужках: `{task.title}`, `{tasks.length}`.
5. **Props** — вхідні дані компонента. Батько передає їх атрибутами: `<TaskItem task={task} />`.
6. Props доступні лише для читання. Дочірній компонент викликає переданий callback, наприклад `onToggle(task.id)`, а батько змінює власний стан.
7. **useState** зберігає локальний стан між рендерами та повертає пару: поточне значення й setter.
8. Пряма мутація може не спричинити очікуване оновлення та змінює попередній знімок стану. Створюють нові масиви й об’єкти.
9. `setState(value)` задає конкретне наступне значення. `setState(prev => ...)` обчислює його з актуального попереднього стану, що важливо для черги оновлень.
10. `map` перетворює кожний елемент масиву на React-елемент: `tasks.map(task => <TaskItem key={task.id} ... />)`.
11. **key** допомагає зіставляти елементи між рендерами. Індекс нестабільний при видаленні чи перестановці й може прив’язати локальний стан до іншого елемента.
12. **Умовний рендеринг** обирає розмітку за умовою: if з раннім return, тернарний оператор або &&.
13. State належить компоненту й змінюється його setter-ом. Props надходять від батька й не змінюються дочірнім компонентом.
14. Спільний state піднімають до найближчого спільного батька; тут це App.
15. Setter ставить оновлення в чергу; React обчислює новий результат і оновлює потрібні частини DOM. У поточному обробнику значення стану залишається знімком поточного рендера.
16. Статистика є похідною від tasks і обчислюється через length/filter; окремий state створив би ризик розсинхронізації.
17. **Immutable update** зберігає попередні значення незмінними: додавання через spread, видалення через filter, перемикання через map і `{ ...task, completed: !task.completed }`.
